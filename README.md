# قالب تطبيق تعليمي — النسخة النظيفة

هذه نسخة أساس قابلة لإعادة الاستخدام لبناء تطبيق جديد لمادة أو معلم جديد دون إعادة بناء الواجهة من الصفر.

## الفكرة

الواجهة ثابتة، والهوية والمنهج ومحتوى الدروس منفصلة في ملفات بيانات:

- الهوية والألوان والتواصل: `src/data/teacher.json`
- فهرس المنهج: `src/data/curriculum.json`
- محتوى كل درس: `src/data/lessons/<lesson-id>.json`
- منطق التحقق من البيانات: `src/content/schema.ts`

## ابدأ من هنا

1. عدّل `src/data/teacher.json` وضع اسم المعلم والهوية والألوان ووسائل التواصل.
2. عدّل `src/data/curriculum.json` وضع الصف أو المرحلة والمادة والوحدات والدروس.
3. أنشئ ملفًا لكل درس داخل `src/data/lessons/` باستخدام نفس `id` الموجود في المنهج.
4. أضف الموارد تدريجيًا داخل ملف الدرس فقط: شرح، تلخيص، فيديو، نشاط، تقويم، ملفات، واجب.
5. لا تعدّل Components أو التنقل أو Schema عند تحديث محتوى عادي.

## التشغيل والفحص

استخدم Node.js 22.12 أو أحدث وnpm:

```bash
npm install
npm run dev
```

وقبل النشر:

```bash
npm run validate:content
npm run typecheck
npm run test:run
npm run check
npm run build
```

## قاعدة التحديث

عند إضافة محتوى إلى درس موجود، عدّل أقل عدد ممكن من الملفات، وغالبًا ملف الدرس فقط. لا تغيّر الهوية أو التصميم أو التنقل أو Components إلا بطلب صريح.

## الموارد

- الروابط الخارجية: HTTPS فقط.
- الملفات المحلية: داخل `/public/assets/` ويُشار إليها بمسار يبدأ بـ `/assets/`.
- الفيديوهات والألعاب والملفات الكبيرة يُفضّل أن تبقى روابط خارجية عندما يكون ذلك أنسب حتى يظل المستودع خفيفًا.

## حدود القالب

التطبيق مكتبة تعليمية ثابتة بلا تسجيل دخول، ولا قاعدة بيانات، ولا LMS، ولا Backend، ولا تتبع درجات أو تقدم. يمكن إضافة هذه الوظائف لاحقًا كمشروع مستقل إذا لزم، لكنها ليست جزءًا من النسخة الأساسية.

راجع `TEMPLATE_START_HERE.md` قبل بناء أي تطبيق جديد، و`AGENTS.md` عند تنفيذ تحديثات محتوى لاحقة.
